KV cache gradient leakage in autoregressive video training

An inherited autograd bug, a two-line fix, and its effect on DMD training.

Donglin Yang

This bug was identified during my internship at Tencent ARC Lab.

01 Mechanism 02 The fix 03 Results 04 Videos 05 Code audit

Self Forcing is designed to block gradients across chunks, but its training code unintentionally allows them to leak through the KV cache. This changes the intended training gradients and increases GPU memory usage. Downstream implementations that inherit the same cache-update pattern also inherit the bug.

How a fresh cache keeps a stale graph

Self-forcing training generates a video one chunk at a time. Within each chunk, the forward pass at a selected denoising step—the exit-step forward pass—runs with gradients enabled. Its output contributes to the training loss. The model then performs a context refresh under torch.no_grad(), updating the cache with K/V computed from the generated chunk.

Both forward passes write to the same persistent cache buffers. The exit-step forward pass records an autograd connection through its in-place write, typically via CopySlices. The subsequent no-grad refresh overwrites the values without removing that connection. When the next chunk reads the cache, its gradients can flow back into the earlier exit-step forward pass.

PyTorch’s no_grad() disables recording of new operations; it does not retroactively detach an existing tensor. detach() explicitly disconnects a tensor from its autograd history. These connections keep earlier computation graphs alive across chunks, increasing GPU memory usage.

A minimal reproduction

import torch


def probe(detach_cache=False):
    w = torch.ones(1, requires_grad=True)
    cache = torch.zeros(4)

    # Earlier chunk: a differentiable, in-place cache write.
    cache[:2] = w * 2

    # Refresh: replace the values without recording a new graph.
    with torch.no_grad():
        cache[:2] = 5.0

    if detach_cache:
        cache = cache.detach()

    # A later chunk reads the refreshed context.
    q = torch.tensor(3.0, requires_grad=True)
    loss = (cache[:2] * q).sum()
    grad_w, grad_q = torch.autograd.grad(loss, (w, q), allow_unused=True)
    return loss.item(), None if grad_w is None else grad_w.item(), grad_q.item()


print(probe(False))  # (30.0, 12.0, 10.0)
print(probe(True))   # (30.0, None, 10.0)

Each tuple contains the loss, the gradient with respect to w, and the gradient with respect to q. None means that the loss is no longer connected to w; the gradient with respect to q is unchanged.

Download the CPU reproduction and run python kv_cache_gradient_leak.py with PyTorch installed.

The fix: detach the cache at the boundary

After refreshing the context, detach both K and V in every layer before generating the next chunk:

# Preserve the current chunk's connection to the training loss.
outputs.append(denoised_pred)

with torch.no_grad():
    refresh_context(denoised_pred, kv_cache)

# Stop gradients through persistent context, not through the output above.
for layer_cache in kv_cache:
    layer_cache["k"] = layer_cache["k"].detach()
    layer_cache["v"] = layer_cache["v"].detach()

Apply .detach() at every chunk boundary, after the cache-update forward pass represented by refresh_context. Detachment shares the existing storage and preserves cached values. The current chunk’s output remains connected to the training loss.

Recomputing context offers another way to avoid this leak. Self Gradient Forcing (SGF) performs a no-grad rollout, then re-encodes the recorded context latents in a separate gradient-enabled forward pass. This gives the backward pass a fresh graph corresponding to the context computation used in that forward pass, avoiding the stale cache connections described above. Detachment restores Self Forcing’s zero cross-chunk gradient boundary; SGF instead enables gradients through recomputed context K/V while keeping the generated context latents detached.

Results

We compare DMD training with and without KV cache detachment using two few-step initializations: Causal Forcing’s ODE checkpoint (causal_ode.pt) and Causal Forcing++’s CD checkpoint (causal_cd.pt).

Memory and gradient norms

Blocking unintended cross-chunk gradients also lowers the generator gradient norm during training. Across the logged steps, the mean falls from 0.1483 to 0.0921 (−37.9%) with ODE initialization and from 0.1307 to 0.0830 (−36.5%) with CD initialization.

VBench after 750 DMD iterations

Detachment improves video dynamics with both initializations, reflected in higher Dynamic Degree scores. The overall VBench score is nearly unchanged with ODE initialization and lower with CD initialization.

Dynamic Degree during training

With CD initialization, detachment yields higher Dynamic Degree at every evaluated checkpoint. With ODE initialization, the initial advantage diminishes during training and reverses at 1500 iterations.

✓ Likely LongLive 1.0 LongLive1.0 · 31c70d9
Gradients can flow between adjacent blocks in a chunk
The streaming trainer detaches K/V before computing the critic loss. By then, the generator has already processed the chunk. Each exit-step forward pass applies the K/V writes, and the next block reuses the same cache after a no-grad refresh.
✓ Likely LongLive 2.0 LongLive2.0 · 31c70d9
Non-quantized KV cache
With a non-quantized KV cache, the generator reads historical cache through cat or clone, writes undetached K/V, and refreshes under no_grad().
✓ Possible Rolling Forcing RollingForcing · a1477d0
Rolling-window training
A gradient-enabled window forward pass and no-grad refresh share a cache with in-place K/V writes. The rolling-window gradient behavior remains unverified.
✓ Possible DistillAlign DistillAlign · 00eac44
Training rollout not released
The released attention implementation contains the same in-place K/V write and cache read. The training rollout is not included in this release.
✓ Possible OPSD-V OPSD-V · 0f4b9b6
Default settings detach; an optional mode does not
The released Self-Forcing and LongLive training configurations set opsd_backward_per_chunk=true, which detaches caches after each backward pass, as specified in Algorithm 1. Setting it to false skips detachment: persistent K/V writes retain their graph across the no-grad refresh, and later cache reads can propagate gradients into earlier chunks.
✗ No Self Gradient Forcing Self_Gradient_Forcing · 79be9ac
Recomputed context gradients
The entire serial rollout and refresh run without gradients; gradient-enabled replay recomputes context from detached latents. Backward differentiates the replay computation, avoiding stale rollout-cache connections.
✗ No Causal-rCM rcm · ed3cb14
Detached writes; read-only cache access
Persistent K/V writes explicitly detach, while the gradient-enabled exit-step forward pass uses READONLY. The current chunk remains differentiable; cached context is detached.
